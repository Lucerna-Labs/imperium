# Static causal network-world passage — revision 6 precommit

## Resolved definition

Jesse instructed the agent to resolve the endpoint/service question using how
static filters work and continue the functional filter. The fixed world
contains explicit conditional relationships with variables, ranges and CIDR
patterns. An individual connection does not need its own memorized training
record when it instantiates one of those represented relationships. Fields
constrained by a relationship must satisfy it; unspecified fields are variables
only where the world explicitly declares that scope. No implicit wildcard,
online learning or expansion from arriving traffic is allowed. Unsupported,
unresolved or unrelated structure has no complete passage relationship.

This is the admission contract; an independent allow-rule engine cannot
substitute for it. Conditions, graph truth and full 48D coordinates are bound
into one immutable world identity. Passive admission returns the applicable
causal neighborhood. Only an exact packet linked to a complete represented
path can be transferred by the packet adapter. Lightcone stays unsealed.

## Implementation ownership

1. Sourced typed world records describe IP/transport validation, flow
   progression and declared endpoint/service patterns. Synthetic deployment
   patterns are explicitly operator/lab declarations, not facts attributed to
   an RFC. Training never changes these facts or manufactures edges.
2. The owning Lightcone service composes fact input, condition-sensitive exact
   graph admission and receipts. Full trained geometry is retained; observer
   projection and learned proximity cannot create passage relationships.
3. The host parser/state tracker supplies bounded factual context from exact
   kernel-held bytes. Previewed flow changes are committed only after the
   corresponding packet passes; rejected input cannot poison future state.
4. The host kernel adapter releases only the same owned held packet bound by
   its query hash. Native mesh/TUN data has no separate packet-passage bypass.
   Geometry failure/absence and unsupported traffic stay blocked. There is no
   causal allow/deny judge inside Lightcone.

The old v4 world and every prior failure remain unchanged. Revision 6 is a
fresh condition-sensitive network-world artifact; earlier invalid v5 artifacts
are not promoted. Local training/VM acceptance does not imply a seal or
accelerator acceptance.

## Frozen initial operational corpus

All supported IPv4/IPv6 TCP and UDP forms, IPv4 ICMP echo, represented ARP/NDP
structure and the native authenticated mesh are in scope. Fragments without
reassembly, unrepresented ICMP forms, invalid checksum/length, unknown network
or link protocols and invalid flow progression cannot inherit a nearby
positive relation. Preserve kernel checksum/offload context without calling
an unfinished kernel checksum a valid observed wire checksum.

The owned lab declares variable endpoint patterns for its private networks,
tunnel prefixes and loopback, with explicit synthetic test services. A new
ephemeral source port/endpoint within a represented pattern is a positive
instance; the same packet shape outside its endpoint/service pattern is a
negative instance. These lab declarations are not this physical host's
production service policy.

Freeze exact catalog, source hashes, mechanism splits, train configuration,
controls and packet fixtures before training. Required controls: complete
condition-sensitive graph, conditions ignored, shuffled context, negative and
unknown facts, cold/untrained relations, and full-coordinate/observer separation.
No admission threshold may be adjusted after observing an evaluation failure.

## Required runtime evidence

Three fresh isolated VMs must independently log source bytes, hub ingress and
egress, receiver bytes and exact receipt joins. Positive TCP/UDP/ICMP cases
must arrive. Matched undeclared service/endpoint, orphan or out-of-range flow,
unsupported/fragmented/malformed and unavailable-geometry cases must not
arrive. Reader loss retains a kernel block; explicit recovery restores the
same represented positive traffic. Require zero reported capture loss and
zero truncated captures. Record every failed setup/control. Scope remains
the actual owned interfaces/namespaces and supported catalog revision.

This precommit resolves the earlier pending semantic question. It records an
implementation/training/testing obligation, not a completed filter.
